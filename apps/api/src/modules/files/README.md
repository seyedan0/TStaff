# ماژول files

## مسئولیت و دامنه داده
مدیریت متادیتای اشیاء، شناسه خصوصی، فرآیند آپلود و اسکن بدافزار، و صدور لینک‌های امن

## لایه‌بندی داخلی
- domain/: موجودیت‌ها، قوانین خالص و مدل‌های تغییرناپذیر.
- application/: واسط‌های کاربردی، پورت‌ها و سرویس‌های دامنه.
- infrastructure/: ریپازیتوری‌های دیتابیس و آداپتورها.
- presentation/: کنترلرهای REST و اعتبارسنجی ورودی‌ها.

## قواعد مرزبندی
- دسترسی به این ماژول از سایر بخش‌های سیستم صرفاً از طریق توابع عمومی صادرشده در index.ts یا رویدادهای صف Outbox مجاز است.

## ذخیره‌سازی خصوصی و مهاجرت CHG-FILES

مرتبط با FR-014، FR-016، FR-058، AT-18 و AT-30. باینری فایل در جدول SQL ذخیره نمی‌شود؛ `stored_objects` فقط شناسه، کلید، ارائه‌دهنده، bucket، اندازه، نوع، بارگذار و وضعیت اسکن را نگه می‌دارد.

- `FILE_STORAGE_PROVIDER=LOCAL` از `PRIVATE_FILES_DIR` استفاده می‌کند. این پوشه باید خارج از فایل‌های عمومی وب و روی دیسک پایدار باشد. مقدار پیش‌فرض توسعه `var/private-files` است.
- `FILE_STORAGE_PROVIDER=S3` از تنظیمات `S3_ENDPOINT`، `S3_REGION`، `S3_BUCKET`، `S3_ACCESS_KEY`، `S3_SECRET_KEY` و `S3_FORCE_PATH_STYLE` استفاده می‌کند. اعتبارنامه فقط از محیط خوانده می‌شود. کلید و رمز باید با هم تنظیم شوند؛ بدون آن‌ها زنجیرهٔ استاندارد اعتبارنامهٔ SDK استفاده می‌شود.
- bucket باید خصوصی باشد و دسترسی عمومی آن در ارائه‌دهنده مسدود شود. آداپتور هیچ ACL عمومی یا نشانی عمومی صادر نمی‌کند. در صورت پشتیبانی ارائه‌دهنده می‌توان `S3_SERVER_SIDE_ENCRYPTION=AES256` را تنظیم کرد؛ سیاست رمزگذاری bucket و ارتباط TLS در استقرار تنظیم شوند.
- در محیط production، ارائه‌دهنده باید صریح تعیین شود؛ مقدار ناشناخته به فایل‌سیستم محلی بازنمی‌گردد.
- مهاجرت دیتابیس فایل‌های قبلی را `LOCAL` علامت می‌زند. تغییر ارائه‌دهندهٔ پیش‌فرض فقط روی آپلودهای جدید اثر دارد. برای هر دانلود یا اسکن مجدد، ارائه‌دهنده و bucket ثبت‌شدهٔ همان فایل استفاده می‌شود. انتقال دادهٔ واقعی عملیات جداگانه است؛ تا پایان انتقال معتبر، پوشهٔ قبلی حفظ شود.

اندازهٔ فعلی حداکثر ۲۵ مگابایت و انواع مجاز PDF و DOCX هستند. دادهٔ فایل پیش از نوشتن اعتبارسنجی می‌شود. فایل تا پاسخ سالم اسکنر در قرنطینه باقی می‌ماند؛ شکست ثبت فراداده باعث تلاش برای حذف شیء خصوصی می‌شود و خطای پاک‌سازی بدون درج نام فایل یا اطلاعات تماس در لاگ ثبت می‌شود.

## دسترسی به دانلود

بارگذار فایل سالم را می‌بیند. برای سایر افراد، policy فقط از سرویس عمومی ماژول منابع یا داوری، پروندهٔ واقعاً متصل به فایل را پیدا می‌کند و سپس از سرویس عمومی پژوهش مجوز آن پرونده را می‌گیرد. داشتن نقش مدیریتی یا مشاهدهٔ بانک منابع به‌تنهایی مجوز دانلود نیست. انتساب لغوشده و انتساب مدیر به پروندهٔ دیگر مجوز ایجاد نمی‌کنند. کتابخانه مسیر انتشار و کنترل مجوز مستقل خودش را دارد.

## آزمون‌ها

`pnpm --filter @tstaff/api test -- src/modules/files`

سناریوها شامل قرنطینه، آلودگی، محدودیت اندازه، اندازهٔ جعلی، ذخیرهٔ صرفاً فراداده، پاک‌سازی شکست ثبت، خواندن فایل محلی پس از تغییر پیش‌فرض به S3، bucket تاریخی، رد مدیر نامرتبط و دارای دسترسی صرفاً به بانک، و دسترسی همکار علمی فقط به فایل پروندهٔ مرتبط هستند. S3 در آزمون واحد در مرز SDK شبیه‌سازی می‌شود؛ صحت bucket واقعی و بازیابی فایل‌ها باید در محیط آزمایشی دارای زیرساخت مستقل نیز بررسی شود.
