# داده‌ی نمایشی نسخه‌ی Vercel

**دامنه:** فقط نسخه‌ی مرورگری دمو و اجرای محلی وب، بدون ساخت رکورد در پایگاه داده.

## هدف

دموی استاتیک Vercel باید بدون API و دیتابیس قابل بازبینی باشد. همان fixtureهای TypeScript در اجرای محلی روی `localhost` و میزبان‌های `vercel.app` خوانده می‌شوند تا فهرست حساب‌ها، وضعیت‌های پذیرش و کتابخانه در هر دو محیط یکی باشد.

## داده‌های نمونه

- حساب‌های ساختگی برای کارآموز در حال مطالعه، کارآموز در انتظار ارزیابی، کارورز ارتقایافته، مدیر علمی و مدیر استانی.
- پرونده‌های متقاضی در وضعیت‌های پیش‌نویس، داوری، تأیید و رد. مطابق `FR-001` و `FR-002`، متقاضیِ تأییدنشده حساب ورود ندارد؛ تأیید در دمو یک حساب نمایشی ایجاد می‌کند.
- یک پرونده‌ی پژوهشی نمونه برای کارورز با چهار مرحله و سابقه‌ی منابع، تبیین، تجویز و سناریوی در انتظار داوری.
- سه سند آموزشی نمونه با دو نسخه‌ی الزامی و یک مرجع اختیاری؛ فایل‌ها برای دانلود در `apps/web/public/demo-documents/` قرار دارند و روی خود سند مشخص شده‌اند که رسمی نیستند.
- یک درخواست ارزیابی در انتظار برای نمایش snapshot نسخه‌های مطالعه‌شده به مدیر علمی.

## رفتار و محدودیت‌ها

- ورود از انتخاب یک persona استفاده می‌کند؛ گذرواژه، token یا کاربر واقعی ساخته نمی‌شود.
- پیشرفت مطالعه، درخواست ارزیابی و تغییرات وضعیت دمو در `localStorage` همان مرورگر ذخیره می‌شوند. هیچ تغییر بین مرورگرها یا میان کارفرما و محیط محلی همگام نیست.
- دکمه‌ی بازنشانی در نوار بالا seed همان مرورگر را به وضعیت اولیه برمی‌گرداند.
- اجرای محلی با `pnpm --filter @tstaff/web dev` روی `localhost` همان seed را فعال می‌کند؛ برای اجرای متصل به API واقعی می‌توان `VITE_DEMO_MODE=false` را تنظیم کرد.
- بارگذاری و بایگانی فایل در نسخه‌ی استاتیک فعال نیست؛ مدیریت کتابخانه صرفاً اسناد نمونه را نشان می‌دهد. دانلود فایل‌ها از assetهای خود وب انجام می‌شود.
- این داده‌ها مسیر مجوز یا احراز هویت محصول را شبیه‌سازی می‌کنند و جایگزین اجرای API برای پذیرش نهایی نیستند.

## ردیابی نیازمندی‌ها

- وضعیت‌های پرونده‌ی پذیرش و قاعده‌ی ایجاد حساب پس از تأیید: `FR-001`, `FR-002`, `AT-01`.
- نمایش پرونده‌ی کارورز و مراحل وابسته: `FR-041`, `AT-04`, `AT-20`.
- فهرست و دانلود اسناد کتابخانه و جدایی آن از پیوست پرونده: `FR-006`, `FR-007`, `AT-35`, `AT-36`.
- مطالعه‌ی نسخه‌های الزامی، snapshot درخواست و دسترسی پس از ارتقا: `FR-006`, `AT-37`, `AT-38`.

این fixture داده‌ی نمایشی است؛ پوشش پذیرش امنیتی و منفی مجوزها باید با API واقعی و آزمون‌های AT-35 تا AT-38 انجام شود.
